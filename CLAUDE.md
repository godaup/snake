# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

**Snake Quest**: a level-based snake game built on [Pyxel](https://github.com/kitao/pyxel) (retro game engine, Pyxel 2.x API) with OmegaConf for YAML config. It's distributed as `snake-quest` (the name `snake` is taken on PyPI). The code lives in `src/snake_quest/`, and everything is configured in `pyproject.toml`: hatchling build, dependencies, the `dev` dependency group, the `snake-quest` console script, ruff and pytest. Game data (`settings.yaml`, `levels/`, `resources/*.pyxres`) is package data next to the code and is located via `Path(__file__).parent`. Module imports are absolute (`from snake_quest.map import Map`). `ROADMAP.md` holds the plan (20 levels in 4 arcs, milestones M0–M5): tick its checkboxes when a milestone item is done.

Pyxel is pinned to exactly `2.9.9` (uploaded 2026-08-12). In October 2026 the upstream author's GitHub account (`kitao`) was suspended after his token was abused in the "GhostAction" attacks, and the pin keeps out any release published during that time. Don't widen it until the account is back and new releases can be checked against the upstream repo. Until then, github.com/kitao/pyxel returns 404, and the docs are mirrored at kitao.dev/pyxel.

**Never call `pyxel.playm`.** In Pyxel 2.9.9 it can deadlock with the SDL audio thread: it holds the channels lock while waiting for SDL's audio lock, and the audio callback holds SDL's lock while waiting for the channels lock. The game froze on a music change (reproduced and confirmed from a core dump). `SoundManager.play()` starts each channel with `pyxel.play(ch, sounds, loop=True)` instead, which survived 100k+ rapid switches. `test_game_code_never_calls_playm` guards this. After upgrading Pyxel, rerun `tools/audio_stress.py ... playm` to see whether the bug is gone. Headless Pyxel runs no audio thread, so audio deadlocks only show with the real SDL drivers (`SDL_VIDEODRIVER=offscreen SDL_AUDIODRIVER=dummy` avoids a window and sound).

## Commands

```bash
pip install -e . --group dev          # editable install + pytest + ruff (pip >= 25.1; Linux also needs system SDL2)
snake-quest                           # run the game (or python -m snake_quest); --level N --scale N --mute --debug
pyxel edit src/snake_quest/resources/garden.pyxres   # edit sprites, sounds and arc 1 tilemaps (level layouts)
snake-quest --level maze --preview maze.png   # render a whole level (walls, entities, path, start) to a PNG
python tools/draft_garden.py decorate|organic ...   # decorate a level's floor / generate a natural layout
python tools/draft_maze.py src/snake_quest/resources/garden.pyxres --level src/snake_quest/levels/maze.yaml \
    --src-tm 2 --dst-tm 3 --seed 7    # regenerate the maze draft around the path tiles (see the script's docstring)
python tools/compose_theme.py src/snake_quest/resources/garden.pyxres   # rewrite the menu theme from its text score
python tools/compose_effects.py src/snake_quest/resources/garden.pyxres # rewrite the sound effects from their text score
SDL_VIDEODRIVER=offscreen SDL_AUDIODRIVER=dummy timeout -s KILL 90 \
    python tools/audio_stress.py src/snake_quest/resources/garden.pyxres game 60   # audio deadlock check
pytest                                # run all tests
pytest tests/test_map.py::test_new_pos_is_free   # run a single test
ruff check . && ruff format --check .            # lint + format check
```

CI (`.github/workflows/ci.yml`) runs lint, format check and pytest. It then builds the wheel and runs `snake-quest --version` from a fresh venv, which catches package data or entry points missing from the build. `levels/_temp.yaml` is a scratch level and is excluded from builds.

## Tests

Tests run against the installed package, so do the editable install first. Tests that need Pyxel (`Map`, state handlers, widgets) rely on the session fixture in `tests/conftest.py`, which calls `pyxel.init(..., headless=True)` once. Request the `assets` fixture to get freshly loaded tilemaps (Map mutates them). `Game` cannot be built in tests because it enters `pyxel.run`; use the `game` fixture (`FakeGame`) instead, which records `change_state` calls in `requested_states`. Known bugs are kept as `xfail(strict=True)` tests, so fixing one makes that test fail until the marker is removed.

## Architecture

**Entry point (`cli.py`).** `main()` parses arguments, turns them into a dict of overrides that `Game(overrides=..., start_level=...)` merges over `settings.yaml` in `reload_settings()`, and only then imports `game`, so `--help` and `--version` don't touch Pyxel. New command-line options should become settings overrides the same way.

**Game loop and state machine (`game.py`, `states/`).** `Game` owns the global config (`settings.yaml`), score, level counter, `SoundManager` and one `GameStateHandler` per `StateID`. `pyxel.run(update, draw)` calls the current handler's `update`/`draw`. `change_state()` stops music, sets mouse visibility and starts the new state's music (`is_visible()`, `get_music()`), but only stores `next_stateID`. The switch happens at the end of `draw()`, so the old state finishes its frame first. Handlers are created once in `Game.start()`, except `RunningStateHandler`, which `restart()` and `level_up()` replace with a fresh instance (and with it a fresh `Map`, `Snake` and `Cam`). Level flow: a new `RunningStateHandler` switches to `MISSION` on its first update (briefing: level, title, `intro`, goal descriptions). Enter goes to `COUNTDOWN` (3-2-1-GO!), then back to `RUNNING`. When `map.check_win()` holds, it switches (once) to `LEVEL_COMPLETE`, which shows a snapshot of the stats (`elapsed` playing time, points since `score_at_start`). Enter there calls `game.level_up()`: either a new `RunningStateHandler` for the next level (`change_state(RUNNING)`, so its mission shows) or `VICTORY` after the last level. Mission, countdown and level complete derive from `OverlayStateHandler` (`states/overlay.py`): every frame it redraws the frozen level via `game.running_handler.draw()`, dims the play area with `pyxel.dither`, and then draws its own panel. Pause is an overlay too. Game over and victory still draw straight onto the last frame, which only works because they hide the mouse cursor and don't animate. Pyxel draws the cursor into the screen image, so **any state that shows the cursor must repaint the whole screen every frame** (cls, a backdrop, or an overlay), otherwise moving the mouse leaves a trail of cursors (`test_pause_redraws_everything_so_no_cursor_trail_remains`).

**Menus (`states/menu*.py`, `highscores.py`, `customize.py`, `credits.py`).** All menu screens share one `Backdrop` (`game.backdrop`: hedge frame, drifting decorations, a demo snake chasing a figure-eight), so the animation continues across screens. Menu input helpers (`up/down/left/right/confirm/back`) live in `menu_common.py`. `pyxel.init` uses `quit_key=KEY_NONE`: Esc pauses in a level and goes back in menus, and quitting is a menu item. `change_state()` calls the new handler's `on_enter()` hook (e.g. the game over screen records the highscore there) and only restarts music when the new state's `get_music()` differs, so menu screens keep the theme playing. Music 1 (`MENU_MUSIC`) is the theme, written by `tools/compose_theme.py` into sounds 8-11 of `garden.pyxres`. Music 0 is reserved for the levels and still empty. Sounds 0-7 are the sound effects (`EFFECTS` in `sound.py`: eat, golden, speed, firefly, portal, hurt, death, win), written from a text score by `tools/compose_effects.py`. Game code plays them with `game.sm.effect(name)` on `EFFECT_CHANNEL` 3 (free while the level music is empty; once it isn't, effects need a channel of their own). Pickups, enemies, portals and thorns play theirs when they happen, game over and level complete in `on_enter()` (after `change_state()` has stopped the music). `FakeGame.sm` is a `FakeSounds` that records the names in `effects_played`.

**Profile (`profile.py`, `palettes.py`).** `game.profile` holds the snake palette name and the top-10 highscores. It is loaded from `pyxel.user_data_dir(*USER_DATA)/profile.json` in `Game.start()` and saved on changes. A missing or corrupt file gives a fresh profile, never a crash. `Snake(colors=palette(name))` takes its colours from `PALETTES`, and `snake.recolor()` switches them live. In tests, `FakeGame` has an unsaved `Profile()` and its own `Backdrop`.

**Time.** Movement-independent timing uses wall-clock `datetime` deltas (`game.dt`, set each update), not frame counts: snake growth delay, `Timer`, enemy behavior and weapon cooldown all work this way.

**Screen layout and coordinates.** The window is `header + area + footer` tall (`settings.yaml`). World coordinates include the header height in y: entity/snake positions are offset by `cfg.header.h`, and tilemap lookups subtract it again (`(pos.y - header.h) // 8`). `Cam` computes a draw `offset` that keeps the snake head centred, clamped so nothing beyond the map edges is shown; maps smaller than the play area are centred (`cam._follow`). Every `draw(offset)` in the world adds it.

**HUD (`hud.py`).** `RunningStateHandler` draws the map through `Cam`, then `Hud.draw()` on top of it. The header shows the level number and title, the score (big digits, `BigText`), the best score and the snake length. The footer has one slot per goal: `goal.status()` plus a progress bar when `goal.progress()` is not None. The `header`/`footer` widgets of `GameStateHandler` are no longer drawn by the running state.

**Campaign (`campaign.py`, `levels/campaign.yaml`).** The campaign lists arcs in order. Each arc has a name, a `resources` `.pyxres` file in `resources/` and its levels by file name. `game.level_counter` is the 1-based number in the whole campaign. `campaign.level(n)` returns a `Level` (name, arc, path, resource file). `--level` accepts a number or a name. Images, sounds and music come only from the top-level `sprites` file, loaded once in `Game.start()`. Every `Map` calls `level.load_tilemaps()`, which loads only the tilemaps of its arc's file, so each level starts from fresh tilemaps. `pyxel.load` replaces the `Tilemap` objects, so never keep a reference to `pyxel.tilemaps[i]` across a load. `pyxel.init()` changes the process's working directory to the directory of the module that calls it, so resolve user-given paths before calling it (as `--preview` does). Winning the last level shows `VictoryStateHandler`. A level file that is not in the campaign fails the tests, unless its name starts with `_` (scratch levels, excluded from builds).

**Levels (`map.py`, `levels/<name>.yaml`).** `Map(level=campaign.level(n))` loads the level file:
- `title` (shown in the header and on the mission screen) and optional `intro`: a list of short lines for the mission screen (at most 52 characters each).
- `tm`: index (0–7) of the Pyxel tilemap in the arc's resource file holding the layout; `width`/`height` in pixels; `start` position.
- `goal`: win conditions, all of which must hold. The types live in the `GOALS` registry in `goals.py`: `score: N` (counted from the level's start score), `length: N`, `exit: true` (head on an `EXIT_TILE`) or `exit: [x, y]` (head on a tile showing that sprite tile), `survive: seconds`, `defeat: N` (entities killed by `hit()`, counted in `map.defeated`; eating doesn't count), `hold_length: {length, seconds}` (in a row) and `collect_all: <entity name>`. A new type is a `Goal` subclass with `key`, `done()`, `describe()`, `status()` (at most 20 characters, shown in the footer) and optionally `progress()` (0..1, for the footer bar) and `update()` (for time-based goals), added to `GOALS`. Unknown or missing goals raise when the map loads.
- `timers`: named entries with `duration`, `frequency` (0 = fire once), `fire_n` (0 = unlimited) and a `callback` of `type: spawn` (`entity:` any name in `ENTITY_NAMES`, optional `pos`, optional `max`: no spawn while that many of the entity are on the map) or `type: grow` (`value`). They are turned into closures by `Map.create_callback`.

Tiles with a fixed meaning live in the tile registry `tiles.py`: `TILE_KINDS` maps each sprite tile to a `TileKind` (floor, wall, path, exit, portal, hazard) and `tile_kind(tile)` looks one up (None for entity sprites). `EMPTY_TILE = (0, 0)` and `WALL_TILE = (0, 3)`, and `map.tile_at(pos)` returns the sprite tile at a world position. Walls are painted with `WALL_TILE` in the editor. When a map loads, `_autotile_walls()` replaces each one with the hedge variant `(mask, 8)` that matches its wall neighbours (mask bits N=1, E=2, S=4, W=8; outside the map counts as wall). So collision checks must use `WALL_TILES`, never `WALL_TILE`. Row 10 holds the special terrain, which stays in the tilemap and is handled by `Map._step_on_tiles()` each update: `PORTAL_TILES` (0-3, 10) in four colours, each colour used in a level exactly twice (otherwise loading raises); the head entering one jumps to the centre of its partner, which stays inactive until the head has left it (`map.portals` maps each portal tile to its partner, and breadcrumb distances go through them). `EXIT_TILE` (4, 10) is what `exit: true` goals look for. `HAZARD_TILE` (5, 10) are thorns: every hazard tile the head enters cuts `HAZARD_CUT` segments (`snake.cut()`), and when the snake is too short `map.snake_killed` is set and the running state switches to game over. Maneuver has two portal pairs (placed with 4 tiles of open floor around them; `draft_garden.py organic` keeps portal, exit and hazard tiles). `DECOR_TILES` (row 9: grass, flowers, a stone) are drawn but walkable and free for spawning; `FLOOR_TILES` is empty plus decorations. `PATH_TILE = (3, 0)` is a level design helper marking the intended route (the maze's pathway). Stage 1 (classic, shared with yummy) has floor decorations, and Maneuver plays from tilemap 4, a natural layout generated by `tools/draft_garden.py organic` (the old geometric one stays in tilemap 1). The maze plays from tilemap 3, a draft generated by `tools/draft_maze.py` from the hand-made layout and path in tilemap 2 (kept for reference): an 8-tile cell grid whose only route to the golden apples walks every path cell in the designed order (the one chain through all path cells ending at the golden apples), with no shortcuts; `test_maze_shortest_way_follows_the_whole_path` checks this. Like entity tiles, path tiles are lifted out of the tilemap when the map loads and kept in `map.path`. They are drawn as breadcrumbs once revealed: `map.reveal_path()` shows all at once, `map.reveal_path(origin=pos)` (what the `Firefly` entity does when eaten) sorts them by walking distance from `pos` and lights them one by one (`CRUMBS_PER_SECOND`). With `debug` on, all are always shown. After loading, a tilemap may contain only terrain tiles (`TERRAIN_TILES`: floor, hedge variants, portal, exit, hazard), and a test fails on any stray tile. Any other tile that matches an entity class's `_img_x/_img_y` (8px-tile coordinates in image bank 0) is spawned as that entity, and the tile is erased from the tilemap at load time. That changes the tilemap in memory, which is why every `Map` reloads its tilemaps.

**Entities (`entity.py`).** Subclass `Entity`, set `_img_x/_img_y` to the sprite tile and override `on_intersect` (snake head touches it), `update` and optionally `hit`. Then register it with `@register("name")`: that puts it in `ENTITY_NAMES` so level files (timers, goals) can refer to it, and in `ENTITY_TILES` (sprite tile → class) so tilemaps can place it. Duplicate names or sprite tiles raise. Pickups so far: `Apple` (+5 length, respawns), `GoldenApple` (+20 length, +5 points), `SpeedApple` (no length, +1 point, `snake.boost(1.5, 5 s)`: `effective_speed` is used for movement, a new boost replaces the running one, and the HUD shows it), `Firefly` (hovers, drifts towards a passing snake; eating one reveals the breadcrumbs for `LIGHT_SECONDS` = 20 s, after which they fade out over `CRUMBS_FADE` s, and another firefly relights them from where it is eaten). Entities are removed by setting `alive = False`. `Map.update` drops dead entities, timers and projectiles at the start of the next update.

**Snake (`snake.py`) and input (`controls.py`).** Every frame `snake.update()` first asks its `controller` (default: `Controller()`, which goes straight and never fires): `steer(snake, map)` returns -1..1 and is multiplied by `snake.turn_speed` (`TURN_SPEED` = 9 degrees per frame), and `fire(snake, map)` triggers the weapon. The player's snake gets a `KeyboardController` (arrows / d-pad, space) in `RunningStateHandler`, the menu's demo snake a `ChaseController` (steers towards `target(snake, map)`, or straight when that is None), and tests use `ScriptedController` (one steering value per frame). Snake code must never read `pyxel.btn` itself; bots, winnability tests and the rival snake all go through this interface (`test_a_bot_can_play_a_level`). The head moves along `orient` (degrees, Pyxel's `cos`/`sin`), and each segment takes the previous position of the one ahead of it. `grow > 0` appends segments one at a time with a delay. `grow < 0` cuts `|grow|` segments every frame for as long as it stays negative (intended), and raises `RuntimeError("Dead")` once the snake is shorter than that. Collisions with walls and entities test two points from `get_collision_points()`, not the whole circle. `Projectile`/`Weapon`/`Gun` live here as well and are only partly wired up: `snake.weapon` is never set.

**UI (`widget.py`).** `Widget` sizes itself automatically from text lines and an optional `ImgInfo` sprite. `add_sub_widget` makes child coordinates relative to the parent. `Button` handles hover, click and an optional hotkey in `update()`. `LifeBar` fills `val` (0–1) of its width with `fg` over `bg`.

Colors and other tuning values are module-level constants (e.g. `TURN_SPEED`, `MAX_SPEED`, `COL_*`) at the top of each file.
