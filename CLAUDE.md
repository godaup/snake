# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

**Snake Quest**: a level-based snake game built on [Pyxel](https://github.com/kitao/pyxel) (retro game engine, Pyxel 2.x API) with OmegaConf for YAML config. It's distributed as `snake-quest` (the name `snake` is taken on PyPI). The code lives in `src/snake_quest/`, and everything is configured in `pyproject.toml`: hatchling build, dependencies, the `dev` dependency group, the `snake-quest` console script, ruff and pytest. Game data (`settings.yaml`, `levels/`, `resources/*.pyxres`) is package data next to the code and is located via `Path(__file__).parent`. Module imports are absolute (`from snake_quest.map import Map`). `ROADMAP.md` holds the plan (25 levels in 5 arcs, milestones M0–M5, then the expansion: arcs 6–7, a bonus arc and one-off levels; `docs/arc5-caves.md` is the design of arc 5): tick its checkboxes when a milestone item is done.

Pyxel is pinned to exactly `2.9.9` (uploaded 2026-08-12). In October 2026 the upstream author's GitHub account (`kitao`) was suspended after his token was abused in the "GhostAction" attacks, and the pin keeps out any release published during that time. Don't widen it until the account is back and new releases can be checked against the upstream repo. Until then, github.com/kitao/pyxel returns 404, and the docs are mirrored at kitao.dev/pyxel.

**Never call `pyxel.playm`.** In Pyxel 2.9.9 it can deadlock with the SDL audio thread: it holds the channels lock while waiting for SDL's audio lock, and the audio callback holds SDL's lock while waiting for the channels lock. The game froze on a music change (reproduced and confirmed from a core dump). `SoundManager.play()` starts each channel with `pyxel.play(ch, sounds, loop=True)` instead, which survived 100k+ rapid switches. `test_game_code_never_calls_playm` guards this. After upgrading Pyxel, rerun `tools/audio_stress.py ... playm` to see whether the bug is gone. Headless Pyxel runs no audio thread, so audio deadlocks only show with the real SDL drivers (`SDL_VIDEODRIVER=offscreen SDL_AUDIODRIVER=dummy` avoids a window and sound).

## Commands

```bash
pip install -e . --group dev          # editable install + pytest + ruff (pip >= 25.1; Linux also needs system SDL2)
snake-quest                           # run the game (or python -m snake_quest); --level N --difficulty NAME --scale N --mute --debug (collision points, hidden path, tile under the mouse)
pyxel edit src/snake_quest/resources/garden.pyxres   # edit sprites, sounds and arc 1 tilemaps (level layouts)
snake-quest --level maze --preview maze.png   # render a whole level (walls, entities, path, start) to a PNG
python tools/draft_garden.py decorate|organic|fortress|temple|cave|scatter|webs|ice|mirror|thorns ...   # decorate a level's floor / generate a natural, fortress, temple or cave layout (--open X Y R keeps an arena free; cave: --fill, --passes, --long for one winding tunnel) / put entity tiles down spread over the level (scatter --entity NAME --count N) / string webs across passages / paint ice, mirrored floor (--bands N: across the level) or thorns (--region X0 X1: only between these columns)
python tools/draft_maze.py src/snake_quest/resources/garden.pyxres --level src/snake_quest/levels/maze.yaml \
    --src-tm 2 --dst-tm 3 --seed 7    # regenerate the maze draft around the path tiles (see the script's docstring)
python tools/compose_theme.py src/snake_quest/resources/garden.pyxres   # rewrite the menu theme from its text score
python tools/compose_music.py src/snake_quest/resources/garden.pyxres   # rewrite the level music from its text scores
python tools/compose_effects.py src/snake_quest/resources/garden.pyxres # rewrite the sound effects from their text score
SDL_VIDEODRIVER=offscreen SDL_AUDIODRIVER=dummy timeout -s KILL 90 \
    python tools/audio_stress.py src/snake_quest/resources/garden.pyxres game 60   # audio deadlock check
python tools/balance.py --levels hunger --seeds 12   # bot win rate per level and difficulty
pytest                                # run all tests
pytest tests/test_map.py::test_new_pos_is_free   # run a single test
ruff check . && ruff format --check .            # lint + format check
```

CI (`.github/workflows/ci.yml`) runs lint, format check and pytest. It then builds the wheel and runs `snake-quest --version` from a fresh venv, which catches package data or entry points missing from the build. `levels/_temp.yaml` is a scratch level and is excluded from builds.

## Tests

Tests run against the installed package, so do the editable install first. Tests that need Pyxel (`Map`, state handlers, widgets) rely on the session fixture in `tests/conftest.py`, which calls `pyxel.init(..., headless=True)` once. Request the `assets` fixture to get freshly loaded tilemaps (Map mutates them). `Game` cannot be built in tests because it enters `pyxel.run`; use the `game` fixture (`FakeGame`) instead, which records `change_state` calls in `requested_states`. Known bugs are kept as `xfail(strict=True)` tests, so fixing one makes that test fail until the marker is removed.

## Architecture

**Entry point (`cli.py`).** `main()` parses arguments, turns them into a dict of overrides that `Game(overrides=..., start_level=...)` merges over `settings.yaml` in `reload_settings()`, and only then imports `game`, so `--help` and `--version` don't touch Pyxel. New command-line options should become settings overrides the same way.

**Game loop and state machine (`game.py`, `states/`).** `Game` owns the global config (`settings.yaml`), score, level counter, `SoundManager` and one `GameStateHandler` per `StateID`. `pyxel.run(update, draw)` calls the current handler's `update`/`draw`. `change_state()` stops music, sets mouse visibility and starts the new state's music (`is_visible()`, `get_music()`), but only stores `next_stateID`. The switch happens at the end of `draw()`, so the old state finishes its frame first. Handlers are created once in `Game.start()`, except `RunningStateHandler`, which `restart()` and `level_up()` replace with a fresh instance (and with it a fresh `Map`, `Snake` and `Cam`). Level flow: a new `RunningStateHandler` switches to `MISSION` on its first update (briefing: level, title, `intro`, goal descriptions). Enter goes to `COUNTDOWN` (3-2-1-GO!), then back to `RUNNING`. When `map.check_win()` holds, it switches (once) to `LEVEL_COMPLETE`, which shows a snapshot of the stats (`elapsed` playing time, points since `score_at_start`). Enter there calls `game.level_up()`: either a new `RunningStateHandler` for the next level (`change_state(RUNNING)`, so its mission shows) or `VICTORY` after the last level. Mission, countdown and level complete derive from `OverlayStateHandler` (`states/overlay.py`): every frame it redraws the frozen level via `game.running_handler.draw()`, dims the play area with `pyxel.dither`, and then draws its own panel. Pause is an overlay too. Game over and victory still draw straight onto the last frame, which only works because they hide the mouse cursor and don't animate. Pyxel draws the cursor into the screen image, so **any state that shows the cursor must repaint the whole screen every frame** (cls, a backdrop, or an overlay), otherwise moving the mouse leaves a trail of cursors (`test_pause_redraws_everything_so_no_cursor_trail_remains`).

**Menus (`states/menu*.py`, `highscores.py`, `customize.py`, `credits.py`).** All menu screens share one `Backdrop` (`game.backdrop`: hedge frame, drifting decorations, a demo snake chasing a figure-eight), so the animation continues across screens. Menu input helpers (`up/down/left/right/confirm/back`) live in `menu_common.py`. The main menu's DIFFICULTY item switches with left/right/Enter and saves the profile; SETTINGS (`states/settings.py`) sets the music and sound volume (0-`VOLUME_STEPS`, `SoundManager.set_volume`: channel gains, the effect channel at the sound volume unless the music plays on it), fullscreen and the screen filter (`pyxel.screen_mode`, `SCREEN_MODES`), saved in the profile and applied by `game.apply_settings()` at start and on each change; the highscores screen pages through the tables with left/right (difficulty) and up/down (arc), starting at the ones played. Checkpoints: `game.level_up()` from an arc's last level saves the arc in `profile.arcs_done`, moves `game.start_level` (where `restart()` begins after a game over) to the next arc's first level and sets the score back to 0: every arc has its own highscores (a score is the points made in one arc), recorded by the level complete screen after an arc's last level, by game over and by victory. PLAY (`game.play()`) opens the level select (`states/select.py`, `StateID.SELECT`): an overview map (`states/worldmap.py`, `WorldMap`) with one region per arc side by side, drawn once into an image from the arc's `map` theme in `campaign.yaml` (`ground` colour, wall `tint`, `decor` and `props` sprite tiles, the 16x16 `boss` sprite) and joined by a road through numbered stops, one per level. Arcs that are not open (`game.unlocked_arcs()`: the first, and each after a finished one) lie under fog, and so does a region after the last arc; an arc's fog lifts the first time it is seen open (`profile.arcs_seen`). Left/right selects an arc (the camera pans to it), and a small snake (`ChaseController` after a point moving along the road) walks the selected arc's road to and fro, crawling over when another is chosen. Choosing an open arc calls `game.start_arc(arc)`. `campaign.arcs` lists `Arc(name, first, last, theme)`, `campaign.arc_of(n)` finds one. `pyxel.init` uses `quit_key=KEY_NONE`: Esc pauses in a level and goes back in menus, and quitting is a menu item. `change_state()` calls the new handler's `on_enter()` hook (e.g. the game over screen records the highscore there) and only restarts music when the new state's `get_music()` differs, so menu screens keep the theme playing. Music 1 (`MENU_MUSIC`) is the theme, written by `tools/compose_theme.py` into sounds 8-11 of `garden.pyxres`. The level music is named in `sound.MUSIC` (garden 0, wilds 2, fortress 3, ouroboros 4, boss 5): each arc in `campaign.yaml` names its `music` (`Level.music`), a level file may name another (`music: boss` in the boss levels), and `RunningStateHandler.get_music()` plays it; the mission, countdown and pause overlays return the same music, so it plays on, while level complete returns None for its jingle. `tools/compose_music.py` writes the tracks from text scores (sections and a form, three voices each: lead, bass, drums) into sounds 16-30, on channels 0-2 only (`MUSIC_CHANNELS`): The Garden (bouncy, G major), The Wilds (a hunting gallop, E minor), The Fortress (a march, C minor), Ouroboros (eerie and circling, A harmonic minor, a vibrato lead) the bosses' (fast and driving, E Phrygian) and The Caves (slow and dripping, D Dorian, quieter than the rest). Render one to a WAV with `pyxel.musics[n].save(path, seconds)` to listen without the game. Sounds 0-7 and 12-14 are the sound effects (`EFFECTS` in `sound.py`: eat, golden, speed, firefly, portal, hurt, death, win, then shoot, pickup and boom), written from a text score by `tools/compose_effects.py`. Game code plays them with `game.sm.effect(name)` on `EFFECT_CHANNEL` 3, which no music uses. Pickups, enemies, portals and thorns play theirs when they happen, game over and level complete in `on_enter()` (after `change_state()` has stopped the music). `FakeGame.sm` is a `FakeSounds` that records the names in `effects_played`.

**Difficulty (`difficulty.py`).** Easy, Medium, Hard and Nightmare. Medium is the reference every level file is tuned for; `difficulty.apply(cfg, game.difficulty)` scales a level's config when `Map` loads it, with the factors in the `difficulty` section of `settings.yaml`: `goals` (score, length, hold_length, survive, defeat; whole numbers stay whole), `helpful` / `hostile` (intervals of spawn timers, chosen by the spawned entity's `hostile` flag), `boss` (the boss class's `pressure` keys times it, its `relief` keys divided, also inside phases), `light` (darkness and the boss's `lights` keys) and `speed` (the snake's start speed, in `RunningStateHandler`). A level can override values per difficulty with `difficulty: {hard: {goal: {score: 70}}}`, merged after scaling. `game.difficulty` is `--difficulty` (setting `start_difficulty`, not saved) or else the profile's choice from the menu. Intro texts must not quote numbers that scale. `tools/balance.py` measures the bot's win rate per level and difficulty, and `tests/test_winnable.py` keeps it within `WIN_RATES`.

**Profile (`profile.py`, `palettes.py`).** `game.profile` holds the snake palette name, the chosen difficulty, the settings, the finished arcs, the arcs seen open on the map and one top-10 highscore table per arc and difficulty (`profile.table(name, arc)`, `add_highscore(score, level, difficulty, arc)`; an old single table loads as Medium's, and entries from before arcs had tables get the arc of their level in `profile.assign_arcs()`). It is loaded from `pyxel.user_data_dir(*USER_DATA)/profile.json` in `Game.start()` and saved on changes. A missing or corrupt file gives a fresh profile, never a crash. `Snake(colors=palette(name))` takes its colours from `PALETTES`, and `snake.recolor()` switches them live. In tests, `FakeGame` has an unsaved `Profile()` and its own `Backdrop`.

**Time.** Movement-independent timing uses wall-clock `datetime` deltas (`game.dt`, set each update), not frame counts: snake growth delay, `Timer`, enemy behavior and weapon cooldown all work this way.

**Screen layout and coordinates.** The window is `header + area + footer` tall (`settings.yaml`). World coordinates include the header height in y: entity/snake positions are offset by `cfg.header.h`, and tilemap lookups subtract it again (`(pos.y - header.h) // 8`). `Cam` computes a draw `offset` that keeps the snake head centred, clamped so nothing beyond the map edges is shown; maps smaller than the play area are centred (`cam._follow`). Every `draw(offset)` in the world adds it.

**HUD (`hud.py`).** `RunningStateHandler` draws the map through `Cam`, then `Hud.draw()` on top of it. The header shows the level number and title, the score (big digits, `BigText`), the best score and the snake length. The footer has one slot per goal: `goal.status()` plus a progress bar when `goal.progress()` is not None. With `--debug` it also draws `debug.draw_overlay()`: a crosshair at the mouse (the cursor is hidden while playing), the tile under it outlined, and a label with its tile coordinates, kind (or the registered `name` of the entity there), sprite tile and map position, for level design.

**Campaign (`campaign.py`, `levels/campaign.yaml`).** The campaign lists arcs in order. Each arc has a name, a `resources` `.pyxres` file in `resources/` and its levels by file name. Arc 1, The Garden (`garden.pyxres`), has levels 1-5; arc 2, The Wilds (`arc2.pyxres`, whose images and sounds are unused copies), starts with Hunted (level 6, tilemap 0) Armed (level 7, tilemap 1), Prey (level 8, tilemap 2), Burrows (level 9, tilemap 3) and Boss: The Alpha (level 10, tilemap 4). Arc 3, The Fortress (`arc3.pyxres`, layouts from `draft_garden.py fortress`: straight walls and towers, drawn as stone with `tint`), starts with Turrets (level 11, tilemap 0), Swarm (level 12, tilemap 1), Ice (level 13, tilemap 2: ice patches from `draft_garden.py ice`; destroy the turrets, then reach the exit) Minefield (level 14, tilemap 3) and Boss: The Core (level 15, tilemap 4, drafted with `--open` to keep its arena free). Arc 4, Ouroboros (`arc4.pyxres`, temple layouts: a border with pillars and short walls, hedges drawn as purple stone with `tint: {3: 2, 11: 14}`), starts with Trail (level 16, tilemap 0) and Mirror (level 17, tilemap 1: `draft_garden.py temple`, then `mirror --bands 3`, mirrored floor across the whole level) Armored (level 18, tilemap 2) and Gauntlet (level 19, tilemap 3: 1280 px long, ice, mirror bands and thorns in stretches painted with `--region`, a golden apple in each, against `time_limit`) and Boss: Ouroboros (level 20, tilemap 4, drafted with `--open`). Arc 5, The Caves (`arc5.pyxres`, cave layouts from `draft_garden.py cave`: caverns from a cellular automaton on a 3-tile grid, joined by tunnels, rock drawn with `tint: {3: 4, 11: 15}`; every level dark; entities in `caves.py`; designed in `docs/arc5-caves.md`), starts with Webs (level 21, tilemap 0: crystals and mushrooms put down with `scatter`, webs with `webs`; against `time_limit`, harder difficulties spawn more crystals) Moles (level 22, tilemap 1), Collapse (level 23, tilemap 2: `cave --long`, 1536 px, the exit at the far end) Bats (level 24, tilemap 3) and Boss: The Brood Mother (level 25, tilemap 4, drafted with `--open`), the campaign's last level. `game.level_counter` is the 1-based number in the whole campaign. `campaign.level(n)` returns a `Level` (name, arc, path, resource file). `--level` accepts a number or a name. Images, sounds and music come only from the top-level `sprites` file, loaded once in `Game.start()`. Every `Map` calls `level.load_tilemaps()`, which loads only the tilemaps of its arc's file, so each level starts from fresh tilemaps. `pyxel.load` replaces the `Tilemap` objects, so never keep a reference to `pyxel.tilemaps[i]` across a load. `pyxel.init()` changes the process's working directory to the directory of the module that calls it, so resolve user-given paths before calling it (as `--preview` does). Winning the last level shows `VictoryStateHandler`. A level file that is not in the campaign fails the tests, unless its name starts with `_` (scratch levels, excluded from builds).

**Levels (`map.py`, `levels/<name>.yaml`).** `Map(level=campaign.level(n))` loads the level file (hot paths such as `tile_xy`/`tile_at` use the plain copies `map.header` and `map.tm`: OmegaConf lookups are slow and bots call them millions of times):
- `title` (shown in the header and on the mission screen) and optional `intro`: a list of short lines for the mission screen (at most 52 characters each).
- `tm`: index (0–7) of the Pyxel tilemap in the arc's resource file holding the layout; `width`/`height` in pixels; `start` position.
- `goal`: win conditions, all of which must hold. The types live in the `GOALS` registry in `goals.py`: `score: N` (counted from the level's start score), `length: N`, `exit: true` (head on an `EXIT_TILE`) or `exit: [x, y]` (head on a tile showing that sprite tile), `survive: seconds`, `defeat: N` (entities killed by `hit()`, counted in `map.defeated`; eating doesn't count), `hold_length: {length, seconds}` (in a row), `time_limit: seconds` (holds until the time is up, then the level is lost: `map.snake_killed`; divided by the difficulty's goals factor, so easier gives more time), `collapse: {speed, start, warn}` (always holds, like a time limit: after `start` s a cave-in front moves out from the start at `speed` px/s along the ways through the level, octile distances (`CollapseGoal._distances`); the floor it reaches becomes `RUBBLE_TILE` (12, 10), a wall for good (`map.fill`), cracked (`CRACK_TILE` (13, 10), walkable) for its last `warn` s; entities there are buried, a caught body is cut off and a caught head is the end; the camera shakes while it is near (`map.shake`, `Cam`); the footer shows its lead; `speed` scales with the goals factor), `collect_all: <entity name>` and `destroy_all: <entity name>` (the same for things that are shot, e.g. nests) and `boss: defeated` (the level's boss beaten; the footer shows its bar). A new type is a `Goal` subclass with `key`, `done()`, `describe()`, `status()` (at most 20 characters, shown in the footer) and optionally `progress()` (0..1, for the footer bar) and `update()` (for time-based goals), added to `GOALS`. Unknown or missing goals raise when the map loads.
- `tint` (optional): colour swaps for drawing the tilemap, `{from: to}` (the Fortress draws its hedges as stone with `{3: 13, 11: 6}`).
- `trail` (optional): `{seconds: S}` makes the tail leave a wall behind (`Map._lay_trail`): each floor tile it leaves (not within `TRAIL_GAP` px of the head; portals, exits, thorns and ice stay) becomes `TRAIL_TILE` (7, 10), its last `TRAIL_CRUMBLE` seconds `TRAIL_CRUMBLE_TILE` (8, 10), and after S seconds the tile it covered again (`map.trail`: tile -> [covered tile, seconds left]). Both are in `WALL_TILES`, so they kill, block shots, hunters' ways and spawning like walls. The bot doesn't cache them as walls (`PathController._wall`) and knows that its body's cells stay blocked for S seconds more (`_vacate`).
- `darkness` (optional): `{light: R}` (and optionally `floor: colour`) makes the play area dark except a light of radius R around the head and around glowing entities (`Entity.light`, px: apples, fireflies). `darkness.py` renders it with an off-screen image (black with key-coloured holes, blitted with that colour key, a second dithered pass for the soft edge), and in dark levels the tilemap's black floor is drawn in `floor` colour so the lit ground shows. Entities are drawn with `colkey=0`. `--debug` shows the whole level. `map.darkness.light` can change while playing (a boss may shrink it).
- `boss` (optional): `{type: <key>, phases: [{after: seconds, ...}], ...}` builds a boss from the `BOSSES` registry in `bosses.py`. A `Boss` subclass has `key`, `title`, `act()` (every frame), `bar()` (0..1, the boss bar at the top of the play area) and optionally `phase_message()` (shown big for `BANNER_SECONDS` when a phase starts) and `next_phase_due()` (by time unless overridden). `self.setting(name)` reads the current phase's value, falling back to the boss section. Goals still decide the win. `Hunger` (level 5): hunger rises by `rise` per second, each meal (`map.eaten`: entities removed without being killed) takes `meal` away, the snake loses `hunger * starve` segments per second (`map.snake_killed` when nothing is left), and the head's light shrinks from `light[0]` to `light[1]` with hunger. `AlphaBoss` (level 10, `alpha`) puts an `Alpha` entity (a 16x16 `Hunter` subclass, sprite (6, 11)-(7, 12), asleep in its lair until the snake comes within `WAKE` px or `LAIR` s pass) at `pos` with `health`; the bar is its health, phases start when it falls `below` a fraction (they may set `speed`), and every `call` s it calls a hunting beetle out of a random nest while fewer than `pack` are about. `CoreBoss` (level 15, `core`) puts a 16x16 `Core` entity (sprite (8, 13)-(9, 14)) at `pos` with `health`; it is `shielded` (shots glint off) while any turret of its ring stands: each phase (by `below`, like the Alpha) builds a ring of `turrets` turrets `ring` px around it, firing every `reload` s with `armor` health each, and every `call` s it launches a drone while fewer than `swarm` are about. `OuroborosBoss` (level 20, `ouroboros`) puts a `Rival` entity at its lair `pos`: a second `Snake` (`rival.body`, palette `Rival.COLORS`) driven by a `RivalController` (a `PathController` whose foe is the player's snake, `prey`: it aims and fires at its head, its threats are the player's body). It eats apples (no points for the player), picks up weapons (`hostile` weapons: their shots hit the player; at most one shot every `reload` s) and, once long enough, hunts the player's head. It has `lives`: its head in a wall, in itself or in the player's body, or being shot shorter than `Rival.MIN` (a shot cuts it where it strikes: `covers` remembers the segment), costs one, and it is back at the lair `respawn` s later, `length` long; phases by `below` (a share of its lives) change `speed`, `length` and `reload`. The player's head touching any of it is the end. `BroodMotherBoss` (level 25, `brood`) puts a 16x16 `BroodMother` (sprite (12, 15)-(13, 16)) in her lair at `pos` with `health`, out of reach up there (shots fly underneath), and `sacs` egg sacs (`EggSac`, a `Nest` that hatches `Spiderling`s every `call` s, placed with open floor around) about the cave; each sac destroyed (shot, or burnt by a flare) costs her a share of a third of her health. Then (phases by `below`) she climbs into the dark (`ceiling`: only her eyes show) and every `drop` s her shadow grows for `warn` s where the head is heading (`shadow`), she lands, crushes what lies under her (`snake.wound`) and spins a ring of webs, and lies dazed for `stun` s (`rest`: the only time shots hurt her; she can't bite); phases may set `hatch` (spiderlings at each landing) and `dim` (the light shrinks from `light[0]` to `light[1]`). Bosses have `defeated(map)` (for the `boss: defeated` goal), `target()` (a body for bots to shoot at: for the Core a ring turret while shielded, for Ouroboros its tail, for the Brood Mother a sac, else herself while dazed) and `danger()` (a circle bots keep out of: where the Brood Mother will land).
- `timers`: named entries with `duration`, `frequency` (0 = fire once), `fire_n` (0 = unlimited) and a `callback` of `type: spawn` (`entity:` any name in `ENTITY_NAMES`, optional `pos`, optional `max`: no spawn while that many of the entity are on the map) or `type: grow` (`value`). They are turned into closures by `Map.create_callback`.

Tiles with a fixed meaning live in the tile registry `tiles.py`: `TILE_KINDS` maps each sprite tile to a `TileKind` (floor, wall, path, exit, portal, hazard) and `tile_kind(tile)` looks one up (None for entity sprites). `EMPTY_TILE = (0, 0)` and `WALL_TILE = (0, 3)`, and `map.tile_at(pos)` returns the sprite tile at a world position. Walls are painted with `WALL_TILE` in the editor. When a map loads, `_autotile_walls()` replaces each one with the hedge variant `(mask, 8)` that matches its wall neighbours (mask bits N=1, E=2, S=4, W=8; outside the map counts as wall). So collision checks must use `WALL_TILES`, never `WALL_TILE`. Row 10 holds the special terrain, which stays in the tilemap and is handled by `Map._step_on_tiles()` each update: `PORTAL_TILES` (0-3, 10) in four colours, each colour used in a level exactly twice (otherwise loading raises); the head entering one jumps to the centre of its partner, which stays inactive until the head has left it (`map.portals` maps each portal tile to its partner, and breadcrumb distances go through them). `EXIT_TILE` (4, 10) is what `exit: true` goals look for. `ICE_TILE` (6, 10) is ice: walkable (but nothing spawns on it), and while the head is on it `snake.grip` is `ICE_GRIP`, so `snake.heading` (where it moves) only turns that share of the way to `snake.orient` (where it points) per frame (`utils.drift`); `map.ice` says whether a level has any. `MIRROR_TILE` (9, 10) is mirrored floor: walkable, and while the head is on it `snake.mirrored` is set and `snake.update()` turns the other way than the controller steers (the HUD shows MIRRORED!); `PathController.steer` steers the other way there itself, as a player who knows it would (`_steer` is its plain choice). `WEB_TILE` (10, 10) is a web (`TileKind.WEB`, walkable, not free for spawning): the head entering one is held (`snake.boost(WEB_SLOW, WEB_HOLD)`) and tears it (`TORN_WEB_TILE` (11, 10), back to a web after `WEB_REGROW` s once nothing of the snake lies on it: `map.torn`); `map.spin_web`/`clear_web`/`tear_web` change them, `map.web` says whether a level has any. While slowed, the segments lie closer, so `snake.neck()` measures the part next to the head that can't be bitten by distance along the body (`NECK` px: 3 segments at any normal speed), and so does the bot's `BODY_SKIP`. `map.dig(tile)` turns rock into floor for good (moles; the border stays) and `map.fill(tile, wall)` the other way (the cave-in); both autotile the walls around and raise `map.walls_version`, which makes the bot's wall cache and the shared walking distances (`map.chase`, `map.flight`) start over. `HAZARD_TILE` (5, 10) are thorns: every hazard tile the head enters cuts `HAZARD_CUT` segments (`snake.cut()`), and when the snake is too short `map.snake_killed` is set and the running state switches to game over. Maneuver has two portal pairs and The Hunger one (placed with 3-4 tiles of open floor around them; `draft_garden.py organic` keeps portal, exit and hazard tiles). `DECOR_TILES` (row 9: grass, flowers, a stone, and the caves' pebbles and crystal shards) are drawn but walkable and free for spawning; `FLOOR_TILES` is empty plus decorations. `PATH_TILE = (3, 0)` is a level design helper marking the intended route (the maze's pathway). Stage 1 (Classic, and Yummy as level 2 in the same room) has floor decorations, and Maneuver plays from tilemap 4, a natural layout generated by `tools/draft_garden.py organic` (the old geometric one stays in tilemap 1). The maze plays from tilemap 3, a draft generated by `tools/draft_maze.py` from the hand-made layout and path in tilemap 2 (kept for reference): an 8-tile cell grid whose only route to the golden apples walks every path cell in the designed order (the one chain through all path cells ending at the golden apples), with no shortcuts; `test_maze_shortest_way_follows_the_whole_path` checks this. Like entity tiles, path tiles are lifted out of the tilemap when the map loads and kept in `map.path`. They are drawn as breadcrumbs once revealed: `map.reveal_path()` shows all at once, `map.reveal_path(origin=pos)` (what the `Firefly` entity does when eaten) sorts them by walking distance from `pos` and lights them one by one (`CRUMBS_PER_SECOND`). With `debug` on, all are always shown. After loading, a tilemap may contain only terrain tiles (`TERRAIN_TILES`: floor, hedge variants, portal, exit, hazard), and a test fails on any stray tile. Any other tile that matches an entity class's `_img_x/_img_y` (8px-tile coordinates in image bank 0) is spawned as that entity, and the tile is erased from the tilemap at load time. That changes the tilemap in memory, which is why every `Map` reloads its tilemaps.

**Entities (`entity.py`).** Subclass `Entity`, set `_img_x/_img_y` to the sprite tile and override `on_intersect` (snake head touches it), `update` and optionally `hit`. Then register it with `@register("name")`: that puts it in `ENTITY_NAMES` so level files (timers, goals) can refer to it, and in `ENTITY_TILES` (sprite tile → class) so tilemaps can place it. Duplicate names or sprite tiles raise. Weapon pickups are `WeaponPickup` subclasses naming their `WEAPON` class: the same kind adds `AMMO`, another kind replaces the weapon carried (`gun` (2, 11), `spread` (2, 13)). Pickups so far: `Apple` (+5 length, respawns), `GoldenApple` (+20 length, +5 points), `SpeedApple` (no length, +1 point, `snake.boost(1.5, 5 s)`: `effective_speed` is used for movement, a new boost replaces the running one, and the HUD shows it), `Firefly` (hovers, drifts towards a passing snake; eating one reveals the breadcrumbs for `LIGHT_SECONDS` = 20 s, after which they fade out over `CRUMBS_FADE` s, and another firefly relights them from where it is eaten). `Critter` (arc 2, (3, 11), not hostile): grazes until the head comes within `FLEE` px, then runs to the neighbouring tile farthest from the head (`map.flight(snake)`: walking distances from the head, shared like `map.chase`) for a random `RUN`, then catches its `BREATH`; on harder difficulties it runs longer and rests less (`helpful` factor). Eaten: `LENGTH` segments, `POINTS` points. Hostile so far: `Hunter` (arc 2, sprites (0, 11) awake and (1, 11) eyes closed): a state machine in `state`. Asleep until the snake comes within `WAKE` px or its random `NAP` is over; then it hunts the tail faster than the snake (`SPEED`, following `map.chase(snake)`: walking distances from the tail, refreshed every `CHASE_EVERY` s and shared by all hunters) for a random `HUNT` time, then rests (eyes closed, `PAUSE`) or takes a detour to a spot `DETOUR_REACH` tiles away (`DETOUR`, `DETOUR_SPEED`), and hunts again. Rest and detour times scale with the difficulty's `hostile` factor, speeds with its `speed`. A bite on the body cuts `CHUNK` segments off the tail and makes it retreat for `RETREAT` s; a bite the snake is too short for, or the head running into an awake hunter, sets `map.snake_killed`. `Nest` (arc 2, (4, 11), hostile, `HEALTH` 2): while the head is within `ALERT` px it sends out a hunting beetle every `SPAWN` s (times the `hostile` factor) while fewer than `BROOD` of its own are alive; it flashes when hit, and running into it is the end. `Turret` (arc 3, (0, 13), glowing eye (1, 13), `HEALTH` 3): while the head is within `RANGE` px and in sight (`map.clear_line`), it turns to it and every `RELOAD` s (times the `hostile` factor) fires a slow hostile shot where the head is heading (`intercept`: turning dodges it), its eye glowing for `WARN` s before. `Drone` (arc 3, (6, 13)): flies over walls (never out of the level) straight for the head, turning at most `TURN` degrees per frame, so it overshoots and loops; touching any segment it stings (`STING` segments, and it is gone without counting as defeated). `Crawler` (arc 3, (7, 13)): a `Hunter` that hunts at once and without breaks, slower than the snake, with `HEALTH` 3. `Knight` (arc 4, (11, 13)): a `Hunter` in armour (`armored`), slower than the snake, with `HEALTH` 2; it flashes when hit and glints when a shot glances off. Arc 5's entities live in `caves.py` (imported at the end of entity.py, so they register too): `Crystal` ((2, 15), glowing, `collect_all`), `Mushroom` ((10, 15), only a light), `Spider` ((0, 15), crawls along the walls (`_ledge` tiles), spins a web every `SPIN` s, at most `WEBS` of its own; crawling into the body it bites `BITE` segments off, head first into it is the end), `Mole` ((3, 15) mound, (4, 15) up: underground it moves through rock to random spots and digs a tunnel five tiles wide (`SPADE`, at most `DIG_LIMIT` tiles), every `SURFACE` s it comes up for `UP` s away from the snake; only then can it be shot or touched: `exposed` (shots and bot aims skip entities that aren't) and `avoid` are properties), `Bat` ((5, 15) asleep, (6, 15) flying: wakes when any light falls on it, flutters at the head and bites `BITE` segments, flees burning flares within `SCARE` px, goes back to its roost after `ROOST` s in the dark; `avoid = False` like drones), `Burning` (a flare come to rest: light 48 for `BURN` s, burns webs and egg sacs it lies against) and the boss's `BroodMother`, `EggSac` and `Spiderling`. `Mine` (arc 3, (5, 13)): dropped by the Mines weapon, armed after `ARM` s, it goes off when a hostile entity comes within `TRIGGER` px and deals `DAMAGE` to every hostile entity within `BLAST` px (sound `boom`); it never hurts the snake, fizzles after `FUSE` s and, like anything with `tally = False`, counts neither as defeated nor as eaten. Spawn timers can send a wave (`count:` entities at once, each at its own spot), keep out of `clear:` circles (`[[x, y, radius]]` in world px, e.g. no turrets at the exit) and can keep new entities `away:` px from the head (`map.new_pos(away=...)`) and tune them for the level with `with: {SPEED: 1.1}` (settings the class has). The bot (`PathController.threats`) keeps `THREAT` px (growing along an arc) from awake and `SLEEPER` px from sleeping hostile entities, more from bigger ones, and `BODY` px from every other segment of a rival snake's body, except those with `avoid = False` (drones: a sting costs less than swerving around a swarm). Entities are removed by setting `alive = False`. `Map.update` drops dead entities, timers and projectiles at the start of the next update.

**Snake (`snake.py`) and input (`controls.py`).** Every frame `snake.update()` first asks its `controller` (default: `Controller()`, which goes straight and never fires): `steer(snake, map)` returns -1..1 and is multiplied by `snake.turn_speed` (`TURN_SPEED` = 9 degrees per frame), and `fire(snake, map)` triggers the weapon. The player's snake gets a `KeyboardController` (arrows / d-pad, space) in `RunningStateHandler`, the menu's demo snake a `ChaseController` (steers towards `target(snake, map)`, or straight when that is None), and tests use `ScriptedController` (one steering value per frame). Snake code must never read `pyxel.btn` itself; bots, winnability tests and the rival snake all go through this interface (`test_a_bot_can_play_a_level`). `PathController(target)` is the level-playing bot: every frame it tries five steering values held for `HORIZON` frames, drops arcs that hit a wall (the same two points as `utils.collision_points`, which the game tests) or its body or that leave no escape (`ESCAPE` frames), and takes the one that passes over the target, else the one ending closest to it. Distances come from a breadth-first search from the target over `CELL` (4 px) cells, recomputed every `FIELD_EVERY` frames: walls block, and so do body cells (inflated by one cell, so it avoids gaps too narrow to steer through) unless the tail will have left them by the time the head gets there; portals are shortcuts. Arcs that leave the target inside their turning circle get `ORBIT_PENALTY` (otherwise it orbits targets until it bites itself). A `LONG` snake also needs room (`_room`), else it follows its tail. `mode` says why it steered (goal, tail, escape, crash). `nearest(Apple, ...)` makes a target function that skips entities right next to a wall while others exist. `tests/test_winnable.py` lets it beat the levels in `bot.LEVELS` (Classic and The Hunger; Yummy's 250 points are beyond it) (first win of a few seeds); after changing a level's balance, run it (and try more seeds to see the win rate). The arcs go through portals like the head does. The head moves along `orient` (degrees, Pyxel's `cos`/`sin`), and each segment takes the previous position of the one ahead of it. `grow > 0` appends segments one at a time with a delay. `grow < 0` cuts `|grow|` segments every frame for as long as it stays negative (intended), and raises `RuntimeError("Dead")` once the snake is shorter than that. Collisions with walls and entities test two points from `get_collision_points()`, not the whole circle. **Weapons (`weapons.py`).** `snake.weapon` (at most one) comes from a pickup: `GunPickup` (entity `gun`) gives a `Gun` with `AMMO` shots or adds them to the one carried; the HUD shows `GUN n` before the length. Every frame `snake.update()` calls `weapon.update(snake, map, fire=controller.fire(...), seconds)`: with ammo and the `COOLDOWN` over it adds `shots(snake)` to `map.projectiles` (sound `shoot`). A `Projectile` flies straight and dies after `LIFETIME`, at a wall, outside the map or on hitting a hostile entity (`hit(dmg)`, a hunter has 1 health, kills count in `map.defeated`); it never hits the snake or pickups. Hostile shots (`Projectile(hostile=True)`, from turrets) hit only the snake: `snake.wound(index)` cuts it at the segment struck (`segment_at`), but never more than half of it (a shot from the front still hits the body just behind a dodging head); a hit on the head costs half the body, and a snake too short for that dies. Ramming a turret wrecks it for half the snake as well. `Spread` (a `Gun` subclass) fires a fan of three, `FAN` degrees apart; `Ricochet` (`ricochet` (3, 13)) a shot that bounces off `BOUNCES` walls (`Projectile(bounces=...)`) and flies longer; `Mines` (`mines` (4, 13), `DROPS`) has no projectiles: its `release()` puts a `Mine` behind the tail. `Laser` (`laser` (10, 13), `PIERCE`) fires a fast, short beam (`Projectile(pierce=True)`, drawn as a streak) that goes through armour and on through everything it hits (each entity once, `struck`). Entities with `armored` (the `Knight`) only take piercing shots: others glance off (`deflect()`, a glint) and are gone. Shots faster than `STEP` px per frame test the points between too, so the beam can't skip over an entity. `Homing` (`homing` (12, 13)) fires slower shots that turn `TURN` degrees per frame towards the nearest hostile entity within `HOMING_RANGE` they can hurt (`Projectile(homing=...)`); its `FAN` makes bots fire with rough aim. `Flare` (`flare` (7, 15)) fires a slow, short `FlareShot` that becomes a `Burning` light where it comes to rest. A new weapon is a `Weapon` subclass with `name`, `COOLDOWN` and `shots()`. The bot shoots (`PathController.fire`) at the nearest hostile entity in range, within `AIM` degrees and with no wall between, and turns to face one that is about ahead, or resting or asleep behind it (mode `aim`); `bot.target` first goes for what a `collect_all` goal asks for, then for an exit once all other goals are done (`ExitGoal.tiles`); while a length or score goal is open and no goal asks for kills (defeat, destroy_all, a boss), it only eats; without ammo it fetches a weapon, while short it stocks `STOCK` shots (pickups of the weapon it carries only: another kind would replace it) and eats, and once long enough it hunts (the boss's `target()` first, then what a `destroy_all` goal names, then any hostile entity but turrets, which it only shoots when they come into its line of fire; armoured ones only with a weapon that pierces, which is also all it aims at them: `nearest(exclude=...)` leaves out subclasses). Its way-finding treats thorns as walls (arcs may still cross them), and a cave-in's cracked floor too. While a boss offers nothing to shoot (`target()` is None) it stocks up on ammo. Arcs also keep `DODGE` px from where hostile shots will be, and simulate drifting on ice. It turns to aim at what it hunts and at anything moving at any range, at hostile entities that never move (no `state`: turrets, nests) only within `DEFENCE` px. Turning to aim stops after `AIM_PATIENCE` frames for as long (an aim that never lines up would circle forever), and pickups within `WARY` px of a hostile entity (`nearest(wary=...)`) are left for last. With a weapon that `DROPS` it never aims: it eats (leading what follows over its mines) and drops one whenever a hostile entity is within `TRAIL` px of the tail.

**UI (`widget.py`).** `Widget` sizes itself automatically from text lines and an optional `ImgInfo` sprite. `add_sub_widget` makes child coordinates relative to the parent. `Button` handles hover, click and an optional hotkey in `update()`. `LifeBar` fills `val` (0–1) of its width with `fg` over `bg`.

Colors and other tuning values are module-level constants (e.g. `TURN_SPEED`, `MAX_SPEED`, `COL_*`) at the top of each file.
